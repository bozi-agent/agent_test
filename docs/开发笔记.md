# AI 资讯工作台（DSH 插件）

左侧边栏底部一个按钮，点开就是一个**全屏工作台**：找选题 → 扫源抓取 → 筛选核实 → 写文案 → 封面标签，全流程都是按钮驱动，面向不写代码的操作者。

> **注**：原来的「⑥ 发布与互动」「⑦ 数据复盘」两个模块**已按需求彻底移除** —— 界面上没有入口，
> 主机侧的 `publishList` / `comments` / `pickFile` / `parseExcel` / `analyzeReview` 五个接口和
> `lib/review.js` 也一起删掉了。

> **不调用任何大模型**：筛选、文案、排版全部是本地规则生成（事实取自你抓到的原文）。
> 这样做的原因见下面「七点一」，简单说就是：插件一旦去调模型，就可能影响你正在用的聊天会话。

---

## 一、安装（两步）

```powershell
# 1) 装进 web 这个 profile（link 方式，不复制文件，改代码就生效）
cd <插件目录>
& "dsh" plugin --profile web add link:"<插件目录>"

# 2) 重启 DSH Web
```

装完确认两件事（一般第 1 步已经自动做好）：

1. `~/.dsh/profiles/web/package.json` 的 `dependencies` 里有
   `"dsh-ai-news-workbench": "link:<插件目录>"`
2. 同一个文件的 `dsh.profile.bundles` 里有 `"dsh-ai-news-workbench"`（**只出现一次**，重复会报重复注册）

### 卸载 / 回滚

1. 删掉 profile 里 `package.json` 的 `dependencies` 那一行和 `bundles` 里那一项
2. 删掉 `~/.dsh/profiles/web/node_modules/dsh-ai-news-workbench`（junction）
3. 重启 DSH

插件的数据都在 `~/.dsh/ai-news-workbench/`，卸载不会动它；想彻底清干净就手动删这个目录。

### 启用 / 禁用

插件市场里可以随时禁用（禁用只写 `~/.dsh/profiles/web/.dsh-market/state.json` 的 `disabled` 列表）。
如果界面出现异常又怀疑是这个插件，最快的办法就是禁用 + 重启，聊天功能完全不受影响。

- **不是全屏**：面板铺满弹窗可用区域（左边让开侧边栏，其余四边贴合，不留缝）、上下左右居中，面板内部自己滚动；
  想要留白就把 `--xmt-panel-inset` 调大（默认 0 = 贴合）
- **一级页 = 5 格网格**（5 张模块卡；虚线入口卡早年已删除，代码里不再渲染），整体在**面板内**水平 + 垂直居中，
  **没有顶部标题行、没有控制室、没有底部操作行**
- **整张卡就是"进入"按钮**：点卡片任意位置进二级界面，右下角不再有单独的「进入」按钮；
  hover 上浮 3px、描边与发光增强，按下缩到 0.98
- **二级页（模块 1~5）顶部没有独立标题栏、也没有面包屑**：
  标题行挪进"操作与结果"卡片里当第一行 —— 左边「**← 返回**（红色按钮）+ 图标 + 模块名 + 状态徽章」，
  **右边同一行放该模块的全部操作按钮**（开始筛选 / 核实通过 / 刷新…）；
  **"操作与结果"标题保留**，在标题行下方；按钮不再单独占一行
- **二级页取消"鼠标悬停上下晃动"**：条目卡/指标卡/建议卡/标题卡 hover 只提亮描边
  （一级模块卡的 hover 上浮按需求保留）
- **设置 / SOP / 日志**三个页面也是红色「**← 返回**」按钮（文案统一成"返回"，不再写"返回工作台主页"）
- 最后一格虚线卡里竖排三行入口：**设置 / SOP / 日志**（它不参与"整卡点击进入"）
- 卡片固定 **150 × 112**，3 列、`gap: 12px`、`padding: 12px`，整块居中（比上一版更紧凑）

- **一级页面不铺结果**，只看状态、挑模块；顶部没有标题栏，
  **关闭方式**：再点一次侧边栏「AI 资讯工作台」（开关），或者按 `Esc`
- **二级页面才是干活的地方**（抓取结果、筛选勾选表、文案、排版都在这里）
- 外观是**深色半透明卡片 + 霓虹状态发光**：
  - 底色：**两块柔光（左上蓝 / 右下绿）+ 135° 深蓝→墨绿主渐变**。
    渐变**画在一个 `position:fixed; inset:0` 的独立背景层 `.xmt-bg` 上**（不再用 `background-attachment`，也不画在会滚动的容器上）——
    背景永远铺满整个视口，**不会随内容高度出现"上下颜色断裂"那条水平分界线**
  - 卡片：**深色半透明底 `rgba(255,255,255,.05)` + 1px 细边 + 14px 圆角**。
    **刻意不用 `backdrop-filter`、没有白色/浅灰底** ——
    之前试过液态玻璃，某些环境（显卡加速被关/远程桌面）会把模糊层渲染成**不透明浅灰白**，字都看不清；
    现在是纯深色半透明底，任何环境都不会翻白，文字保持白色系
  - **背景轻微流动**：再叠一层同样铺满面板的 `.xmt-bg-flow` 光斑，用 `@keyframes xmt-bg-drift`（26s，`ease-in-out`）
    慢慢平移 + 明暗呼吸（透明度 .72→.92），内容层 `z-index:2` 压在两层背景上面 —— 只动背景，文字不跟着晃
    > 两层背景都用 `position:absolute; inset:0`（**只铺满面板内部**）。以前用 `position:fixed` 会铺满整个浏览器视口，
    > 面板外面那圈留白也被渐变填上，看起来就像"还是全屏、没有面板"。
  - **卡片外面一圈柔和彩色发光（呼吸灯）**：直接给卡片本体加 `box-shadow` 的光晕层
    （`--xmt-halo` / `--xmt-halo-soft` / `--xmt-halo-tint`），`@keyframes xmt-halo-breathe`（5s）只改
    **颜色和模糊半径**（0 0 9px → 0 0 14px），**完全不动 transform**，所以卡片位置/大小一点不变。
    > **为什么不用 `::before` 做光斑**：伪元素一旦层叠上下文没算对（`isolation` / `z-index:-1` 没生效），
    > 那层模糊光斑就会糊在卡片脸上 —— 上一版"卡片内部发亮、颜色被冲淡"就是这么翻车的。
    > `box-shadow` 的绘制区域在**边框盒外面**，物理上不可能盖住卡片里的文字，也不可能改变卡片内部的样子。
    > 卡片底色同时改成实底 `#152734`，内发光/高光棱/玻璃渐变全部保留。
    颜色取当前状态色（未开始不发光 / 进行中蓝 / 已完成绿 / 等待确认黄），相位沿用 `--xmt-breathe-delay` 错开。
  - 另外描边上还有一条很淡的流动亮边（`::after` + `mask-composite:exclude` 裁成 1px 框，
    靠 `background-position` 横向扫过），和上面那圈光配合，让发光更"咬合"卡片边缘
  - 立体感（不靠 backdrop-filter）：**左上角一点反光（radial）+ 上亮下暗的玻璃渐变（160°）+
    一条落影 `0 6px 16px rgba(0,0,0,.35)` + 顶部高光棱 `inset 0 1px 0` + 底部暗棱 `inset 0 -1px 0`**
  - 呼吸发光：**只让"状态外发光"那条变强弱**（`@keyframes xmt-breathe`，3.6s 慢周期，`ease-in-out`），
    描边保持稳定；各卡片相位错开 0.45s（`--xmt-breathe-delay`）避免整屏一起闪；
    **未开始（`--xmt-tone-glow: none`）等于不呼吸**；`prefers-reduced-motion` 下所有动画关闭
  - 状态：**外发光 + 内发光两层** —— 未开始灰边不发光 / 进行中蓝 `0 0 24px rgba(59,130,246,.25)` /
    已完成绿 / 等待确认黄；状态文字与描边同色（未开始是灰 `rgba(255,255,255,.4)`)
  - 卡片内容自上而下只有两组、整体靠上（`justify-content: flex-start`）：
    顶部 **图标 16px + 模块名 14px/600/`rgba(255,255,255,.95)`**，下方紧跟
    **状态文字 12px/500（数字直接写在里，如"已存 5 条"）**，再往下留白；
    不再有单独的数字块、也不再有底部说明文字；**整卡可点**，点任意位置进二级界面
  - 网格：`grid-template-columns: repeat(3, 150px)` + `gap:12px`，整块在**面板内**水平+垂直居中；
    ≥1240px 宽时 3 列、再窄降 2 列、≤820px 降 1 列并放开固定高度（防止文字被压）
    > **"铺满 + 居中 + 可滚动"怎么做的**（这里是踩过坑的地方）：
    > ① 弹窗外壳 `.xmt-root`（fixed 定位到侧边栏右边）里放一层 **`.xmt-overlay`**：
    >   `padding:0`（`--xmt-panel-inset` 默认 0 = 贴合，想留白就调大它）；
    > ② **`.xmt-panel` 面板**：`width:100%` + `flex:1 1 auto`，实底 `rgba(11,24,33,.96)`，
    >   **不设 max-width / max-height / 边框圆角**（设了就会在边上留出一圈底色或缝）；
    > ③ 面板里是 **`.xmt-panel-scroll`**：`overflow-y:auto; overflow-x:hidden` ——
    >   内容高时上下滑，但**绝不出现横向滚动条**。
    > 工作台根节点是 `display:flex; flex-direction:column`，**绝对不能写 `overflow:hidden`** ——
    > 写了之后里面的滚动区就滑不动、内容超高直接被裁。
    > 一级页的 `.xmt-page` 走 **`display:contents`**（这一层不参与布局），于是
    > `.xmt-stage`（`flex:1 0 auto; min-height:100%` + `align-items:center; justify-content:center`）
    > 直接撑满滚动区：内容矮 → 卡片在面板正中；内容高 → 舞台长高、滚动区正常上下滑。
    > 安全边距：舞台 `padding:40px 20px`，网格再补 `padding:40px 0`（顶部/底部各留一截，底部内容不会贴边被裁）。
- 弹窗位置 = **左侧让开侧边栏**（实测量侧边栏右边界，量不到就用兜底 260px），右侧其余区域全给工作台。
  这里刻意不去量"右侧内容区"的矩形 —— 之前按内容区算位置，量到了贴右边的窄元素，
  弹窗被压成屏幕最右 1 像素宽的一条缝，看起来就像"点了按钮没反应"（已加回归测试守住）

## 三、第一次用怎么测（照这个顺序点）

1. 点侧边栏「AI 资讯工作台」→ 网格最后一格虚线卡里点「⚙ 设置」：
   - 选账号定位、填人设描述、粘贴 2~3 条历史爆款文案
   - 填「网站清单」：名称 + 网址 + 抓取难度（普通/困难）
   - 点「保存设置」→「← 返回工作台主页」
2. 进「② 扫源抓取 → 开始抓取」：按你填的网站抓最新几条。
   - **进度条**会实时显示「正在抓取第 N / 共 M 个网站：站点名」+ 百分比；
     补详情页日期时会切成「正在读详情页补日期（第几条 / 共几条）」
   - **日期一律从详情页读真实发布时间**（`<time>` / meta（含 `og:release_date`）/ JSON-LD `datePublished`
     → class/id 带 time·date·publish 的容器 → 中文"发布时间："标签 → 全文兜底（只认带时分的））。
     能读到时分就显示成「2026-09-17 14:07」，只有日期就显示日期；
     **读不到日期、或不在「抓取最近几天」范围内的条目直接丢掉**（不会再标「最新」混进来）；
     「最近抓取」精确到 `小时:分钟`
   - 结果列表是**双列**；看到好题目点「存入选题库」→ 成功会弹提示，
     存进去的条目立刻从列表移走、标题栏那个「本次有效 N 条」也跟着减
   - 某个网站抓不到，会显示「⚠ 该网站暂时无法自动抓取，请手动打开查看：链接」，其他网站不受影响
3. 进「③ 筛选核实 → 开始筛选」：按 6 条标准逐项打勾（大厂发布/开源爆款/免费降价/离谱新闻/信息差/可延展），
   **至少勾中 2 项**才会进候选，并给出每一条的勾选理由。总结里的数字、人名、时间、版本号会标黄。
   确认没问题、把要写的那几条勾上 → 点「核实通过」
4. 进「④ 写文案 → 开始写文案」：每条候选给 5 个标题 + 一段正文 + 标签，逐项过发布前检查清单
   （标题不夸张 / 有具体信息 / 有人味 / 无敏感词 / 标签精准 / 第一人称）。点标题卡片可复制。
5. 进「⑤ 封面标签」：点「**打开模板文件夹**」→ 系统资源管理器会直接打开模板文件夹
   （默认是插件目录下的 `assets/templates/`；升级前放在 `~/.dsh/ai-news-workbench/templates/` 的图也照样认），
   把你的模板图（png / jpg / webp / gif，建议 3:4）丢进去 → 回来点一下「刷新」→
   文件夹里的模板会以**缩略图**列出来，**点哪张就把哪张当封面**（选中的那张带绿框 ✓）。
   封面区显示的就是你选中的那张模板**原图**；这一屏还会把每条帖子的标题、内容、标签摆出来，
   标签可以直接在输入框里改 / 删 / 加。**不往图片上叠任何文字，也不生成多张卡片，更不调大模型。**
6. ~~进「⑥ 发布与互动 → 生成发布清单」~~ —— **该模块连同主机侧接口一起删掉了**
7. ~~进「⑦ 数据复盘」~~ —— **该模块连同 `lib/review.js` 一起删掉了**

> 按当前界面，每一步都要进对应模块点它自己的按钮（「开始全部」那个一键入口已按需求从界面上删掉；
> 想加回来的话，`workbench.js` 里的 `doStartAll` 逻辑还留着，接个按钮就能用）。

## 四、它自己会做判断的地方（硬规则，不是 AI 说了算）

| 位置 | 硬规则 |
|---|---|
| 模块3 筛选 | 6 项标准至少勾中 2 项才进候选；不够的丢掉并写明原因（本地按关键词 + 可观察事实判定） |

| 模块4 检查清单 | 标题不夸张 / 有具体信息 / 有人味 / 无敏感词 / 标签精准 / 第一人称，逐项打勾，没过会写清原因 |

（模块6「合规扫描」、模块7「爆款判定 / 伪爆文 / 改词建议」的规则原本在 `lib/rules.js` 和

## 四之二、抓取规则（模块2）

- 每个网站：超时 10s，最多重试 3 次，失败退避重试
- 站点之间随机间隔 1.5~3.5 秒，不猛刷；**每条都会去详情页读真实发布时间 + 抓完整正文**
  （详情页之间间隔 0.25~0.8 秒；没开时间过滤时才用 `fetch.detailMaxPerSite` 省请求，默认 12，
  开了"抓取最近几天"就必须每条都读，否则日期判不出来）
- 解析顺序：你配的 CSS 选择器 → 通用列表结构 → `<article>` → 扫长链接（三级降级）
- 标记为「困难」的网站走本机 Chrome 调试端口抓（要在设置里填端口，默认 `http://127.0.0.1:9222`）
- **日期解析顺序**（模块2 修复重点）：
  1. 你在设置里配的 `dateSelector`
  2. `<meta>`：`article:published_time` / `og:published_time` / `og:release_date` / `pubdate` / `sailthru.date` 等（`content` 写在 `property` 前面也认）
  3. JSON-LD（`<script type="application/ld+json">` 里的 `datePublished` / `dateCreated` / `uploadDate`）
  4. `<time datetime="…">`（优先 `datetime` 属性）
  5. class/id 里带 `time` / `date` / `publish` / `meta` 的容器（只认 120 字以内的短元素，避免整块正文）
  6. 中文标签：「发布时间 / 更新于 / 发布于 …」后面紧跟的那串
  7. 全文兜底：**只认"日期后面紧跟时分"的那串**（`2026-09-18 14:07`），并且同一串出现多次的优先；
     干巴巴一个 `2026-09-17` 很可能是侧栏/相关阅读里别人的日期，宁可判"读不到"也不用它
     （用户反馈的"选今天却抓到 2 天前的内容"就是这么来的）
  - 归一化：`2026年9月17号 14:07` → `2026-09-17 14:07`；`2026-09-17T14:07:33+08:00` → 同上；
    「3小时前 / 昨天 / 刚刚」换算成北京时间；**读不到时分就只写日期，不硬编 00:00**
- **时间过滤（按需求改严）**：读不到日期、或日期不在"最近 N 天"里的条目**一律丢掉**
  （不再标「最新」、不再"整站兜底保留"）；某天确实没有新资讯就是空列表，界面给一句说明
- **正文抽取**：先删干扰区块（相关阅读/热门/评论/侧栏/版权…）→ `<article>` 或按 class 猜正文容器
  → 转纯文本丢干扰行；万一删过头抽出来太短，会自动退回"不删干扰"版本再抽一次，最后再兜底整页文本 ——
  保证不会出现空正文（用户反馈的"原文没有摘要，细节请点链接看"就是这个）
- 单个网站失败不影响其他网站
- **抓取进度**：主机侧在抓的过程中维护一份内存进度（第几个网站 / 共几个 / 当前站点 / 已拿到几条），
  界面每 800ms 拉一次 `GET /xmt-kf/api?action=fetchProgress` 画进度条；抓完置成 `done`（不落盘，重启即清零）

## 七点一、界面是怎么接到主界面上的（官方机制）

用**官方的侧边栏槽位** `sidebar.footer.action` 放一个入口按钮；弹窗就是普通的 React 渲染，
用 `position: fixed` + 量出来的边界覆盖右侧内容区（不需要 DSH 提供额外 API）：

```js
// 入口只注册这一个槽位（它同时是开关）
ctx.slots.inject('sidebar.footer.action', () => ctx.slots.register(
  { name: 'sidebar.footer.action', id: 'ai-news-workbench', order: 20 },
  SidebarEntry, // 内部：按钮 + 打开时的全屏弹窗（共享同一个 open 状态）
))
```

**入口的位置**：这个槽位本身在侧边栏**最底部**（"设置"上面一行），而需求要入口待在
「技能中心」正下方。侧边栏上半部分没有可注册的槽位（「技能中心」自己也是 skill-explorer
插件用 DOM 注入进去的一行），所以这里保持槽位注册方式不变，只把 React 渲染出来的那个
按钮**搬到**「技能中心」下面 —— 见 `lib/client/sidebar-entry.js`：纯 DOM 搬移，不动节点本身，
React 依旧管着它的属性/样式/点击；技能中心晚一步出现或 React 重渲染把它挤开时会自愈，
卸载时先放回原位再交给 React 删（避免 React 删一个"已经不在自己名下的子节点"而报错）。

**入口的长相**：和「技能中心」那一行完全一致 —— 无边框、平时淡灰字（`label-secondary`）、
鼠标悬停时"灰底 + 黑字"（`label-primary`）、点开工作台后保持黑字 + 一层底色，关掉工作台
又回到淡灰。底色和字色都写在注入的样式表里（内联写法盖不住 `:hover`），只有"平时淡灰 +
透明底"用内联做兜底；展开态是一整行（36px 高），折叠态是 36×36 的圆形图标按钮。

弹窗定位（`lib/client/client.js` 里的 `measureLayout()`）：
1. 扫 DOM 找出侧边栏容器（贴左、竖长条），取它的右边界 `sidebarRight`；
   找不到就用兜底值 260px —— 保证**永远不盖住左侧栏**
2. **不再量右侧内容区**：弹窗左边界 = 侧边栏右边界，上/右/下贴视口，宽高直接算出来
   （踩过的坑：按内容区 rect 反推 `right`，量到贴右边的窄元素，弹窗被压成 1px 宽的缝，
   看起来就像"点了按钮没反应"；`node test/ui.mjs` 第 9 组是这条的回归测试）
3. 窗口 resize / 滚动时重新量一次；所有量算都在 try/catch 里，失败也不影响渲染

> 为什么不用 `conversation.view`：那个机制会把工作台变成会话标签页，和「对话」「轨迹」挤在一起。
> 现在的弹窗是"浮在上面"，不占标签位。

### ⚠ 必须声明 `slots` 依赖（这里踩过大坑）

客户端插件必须写 **两处**：

```jsonc
// package.json
"dsh": { "client": { "inject": ["slots"], "platform": "web" } }
```
```js
// lib/client/client.js
export const inject = ['slots']
```

**不声明会怎样**：平台不等 `slots` 服务就绪就调用 `apply`，`ctx.slots` 是 undefined，
注册全部失效 —— 现象就是「侧边栏没按钮」，控制台只有一条
`slots 服务不可用，工作台界面没有注册` 的警告，看着像没生效但又不报错。

### ⚠ 状态仓的快照必须是稳定引用（React #185）

弹窗的开关状态放在 `lib/client/store.js`，侧边栏按钮订阅它。用 `useSyncExternalStore` 时
**`getSnapshot()` 必须返回稳定引用**：如果每次都 `Object.assign({}, state)` 造新对象，
React 会认为状态一直在变 → 无限重渲染 → 页面报
`Minified React error #185`（Maximum update depth exceeded）。
所以那里把快照冻结成一个对象，只在真正变化时替换。`test/store.mjs` 专门守着这条。

### 界面样式：深色玻璃拟态（Dark Glassmorphism）

所有界面样式集中在 `lib/client/ui.js`，**三层结构**：

| 层 | 在哪 | 干什么 |
|---|---|---|
| 设计令牌 | `ui.js` 的 `TOKENS` | 颜色/圆角/间距/字体全在这里（`--xmt-*` 变量），改一处全局跟着变 |
| 样式表 | `ui.js` 的 `ensureStyles()` | 注入一段 `<style id="xmt-kf-style">`，管 `:hover` / `:active` / 动画 / 窄屏降列 |
| 结构 | `workbench.js` + `client.js` | 只写 `className`（用 `CLS.xxx`）和布局，不写颜色 |

为什么必须注入样式表：内联 `style` 写不了 `:hover`、`:active`、`@keyframes`，也写不了媒体查询。
注入是幂等的（带 id，只注一次），**注入失败只丢视觉、不影响功能**（`test/style.mjs` 守着）。

几条硬规则：
- 背景：深蓝→墨绿渐变 `linear-gradient(135deg,#0a1628,#0d1f2d,#0a1f1a)`，`background-attachment: fixed`
- 卡片：`rgba(255,255,255,.05)` + `backdrop-filter: blur(12px)` + `1px solid rgba(255,255,255,.1)` + 14px 圆角
- 状态描边 + 外发光：未开始灰（无发光）/ 进行中蓝 `#3b82f6` / 已完成绿 `#22c55e` / 等待确认黄 `#f59e0b`，
  由 `toneStyle(tone)` 写成 `--xmt-tone` / `--xmt-tone-glow` 两个变量 → 状态切换是渐变不是突变
- 按钮三种：主按钮（蓝底 + 发光）、次级（透明底 + 描边）、文字按钮（无底无框，hover 变白）
- 点击反馈：`:hover { filter: brightness(1.15) }` + `:active { transform: scale(.96) }` + 0.12s 过渡；
  禁用态 `opacity: .4` + `cursor: not-allowed` 且屏蔽 hover
- 异步按钮：`h(Btn, { loading, loadingText })` → 立刻转圈 + 文案变「抓取中…/筛选中…/生成中…」+ 禁用防重复点击
- 动效克制：卡片 hover 上浮 2px、二级页淡入 + 上移 6px，全部 ≤0.3s，不用旋转/闪烁（`prefers-reduced-motion` 时全关）
- 文字一律带透明度的白（`rgba(255,255,255,.95/.72/.45/.30)`），没有纯黑纯白
- 空数据一律显示 `Empty`（虚线框 + "暂无数据"），不留白

两个专用小组件（都在 `workbench.js` 顶部，纯样式不含业务）：
- `markAll(h, text)`：把数字/英文（人名、版本号、40% 这类）包成 `#fbbf24` 高亮，模块3 标题和摘要用
- `CopyButton`：复制成功后按钮变绿显示「✓ 已复制」，1.4 秒还原

**防崩**：
- `apply` 里注册包 try/catch，注册失败只是工作台不可用
- 传给平台的组件都套了错误边界（`Boundary`）：渲染出错只显示一张提示卡，聊天不受影响
- `slots` 服务万一拿不到：只打一条 warn 就返回，不抛错、不影响聊天
- 不用任何"某个 React 版本才有"的 API（`useSyncExternalStore` 等都有存在性判断 + 兜底订阅）
- 主页/二级页各自内部再包一层 try/catch，出错给「回到主页试试」
- 界面只用 `fetch` 打自己的 `/xmt-kf/api`，不碰任何 Harness 内部服务

## 七点二、改过界面代码之后**必须重新打包**

DSH 的客户端插件不是普通 ES 模块，必须是"注册工厂"格式：

```js
window.__ModuleLoader__.load({ id: "包名", factory: (require) => { ...纯脚本，不能有 import/export... } })
```

**如果直接把带 `import` 的源码当 bundle 给浏览器**，会出这套连锁反应：

1. 浏览器执行到 `import` 报 `Cannot use import statement outside a module`
2. 这个 bundle 注册不上自己
3. 组合脚本是一条一条顺序执行的，**它后面所有客户端插件都跟着注册不上**
4. 页面报 `Failed to load plugins ... loaded without registering "xxx"`（报的还是别人家的名字，很容易看错方向）

所以流程固定是：

```powershell
npm run build          # 重新生成 lib/client-dist/client.js
# 然后重启 DSH + 浏览器 Ctrl + F5
```

`test/bundle-check.mjs` 会检查产物里有没有 `import` / `export`，`test/combo-check.mjs`
会按真实加载顺序把所有客户端插件跑一遍，最先跑这两个就知道是不是自己的锅。

## 七点五、遇到问题怎么查（按现象对症）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 页面报 `Failed to load plugins ... loaded without registering ...` | 客户端插件是"一个组合脚本依次执行"，**任一 bundle 抛错，排在它后面的插件就注册不上**，报错会指到后面那个（看着像别人的问题）。本插件踩过的真实原因就是：客户端 bundle 里带了 `import`/`export` | 跑 `node test/bundle-check.mjs`（查格式）和 `node test/combo-check.mjs`（按加载顺序查哪家挂）；改过界面代码就先 `npm run build` |
| 改了界面代码但界面没变 | 忘了重新打包 | `npm run build`，再重启 DSH + `Ctrl + F5` |
| 侧边栏有按钮、点了没反应 | 弹窗其实开了，但被算成了屏幕最右一条 1px 宽的缝（量"右侧内容区"量错了元素） | 已修：弹窗只按"侧边栏右边界 + 视口尺寸"定位；回归测试在 `node test/ui.mjs` 第 9 组 |
| 侧边栏按钮不见了，控制台只有一条 `slots 服务不可用` 警告 | 客户端没声明 `inject: ['slots']`，`apply` 在服务就绪前跑了 | 照上面「必须声明 slots 依赖」检查两处声明，然后 `npm run build` + 重启 DSH |

## 八、已知限制

- **封面标签（模块5）是"纯本地贴图"**：只把标题/正文按固定坐标、字号、颜色贴到你自己放进模板文件夹的底图上，
  **不调大模型、不能 AI 出图**。想要 AI 出图，得自己装 `dsh-tool-imagegen` 并配自己的 API Key
- 封面标签**不再往图片上写标题/正文**：封面就是你选中的那张模板原图（要加字自己用 Canva 之类的加）
- 标签是"本地关键词提取 + 你手动改"的结果，不进主机侧存储：刷新页面后回到自动提取的那一版
- 「打开模板文件夹」在 Windows 上会优先把"已经停在这个文件夹的资源管理器窗口"拉到前台，不会开一堆窗口
- ~~**数据复盘（模块7）是半自动的**~~ —— 该模块连同解析接口一起删掉了
- **筛选/文案是本地规则生成**，质量取决于原文信息量和你设置里填的人设；语气请自己再顺一遍
- 抓取依赖目标网站的结构，改版会导致某个网站抓不到（会明确提示，不会静默失败）
- 界面是小屏自适应（窄屏模块卡片自动降列），但没做过手机端适配
