# dsh-ai-news-workbench

一个给 **DSH（DeepSeek Harness）** 用的侧边栏插件：点一下弹出全屏工作台，把「找选题 → 抓资讯 → 筛核实 → 写文案 → 做封面」这条做号流水线变成**一串按钮**，面向不想写代码的操作者。

> **默认不调用任何大模型。** 筛选、文案、排版全部是本地规则生成，事实来自你抓到的原文。
> 只有「④ 写文案」里的**「AI 润色」**是可选功能，需要你自己填 API Key 才启用 —— 详见「五、模型配置」。

---

## 一、它长什么样

```
侧边栏「技能中心」下面 [AI 资讯工作台]  ← 点开／再点收起
        ↓ 弹出工作台面板（左侧栏不动，右边铺满）
┌──────────────────────────────────────────────┐
│  📚 ① 选题库    📡 ② 扫源抓取   🔍 ③ 筛选核实  │
│  ✍️ ④ 写文案    🏷️ ⑤ 封面标签                 │
└──────────────────────────────────────────────┘
        ↑ 点卡片进二级页：该模块的按钮 + 状态 + 结果区
```

五个模块：

| 模块 | 干什么 |
|---|---|
| **① 选题库** | 平时刷到的好题目随手存进来，写的时候回来挑 |
| **② 扫源抓取** | 按你配置的网站清单抓最近几天的资讯；**每条都会进详情页读真实发布时间**，读不到日期或不在时间范围内的直接丢掉 |
| **③ 筛选核实** | 6 条判断标准（大厂发布 / 开源爆款 / 免费降价 / 离谱新闻 / 信息差 / 可延展）逐项判定，勾中就给候选，你自己点「核实通过」 |
| **④ 写文案** | 把原文的**完整标题 + 完整正文**原封不动搬进来（不改写、不编事实）；想润色语气可以点可选的「AI 润色」 |
| **⑤ 封面标签** | 把标题 / 正文 / 标签摆出来，配合你放进模板文件夹的底图做封面；标签是本地关键词提取，可以手动改 |

## 二、隐私说明（先说清楚）

- **代码里没有任何硬编码的 API Key。** 你填的 Key 只存在**本机**的 `~/.dsh/ai-news-workbench/settings.json` 里，不会随仓库发布，也不会传给第三方。
- 插件的数据（设置、选题库、抓取缓存、文案草稿、日志）**全部落在 `~/.dsh/ai-news-workbench/`**，不在项目目录里。
- 仓库的 `.gitignore` 已经排除了运行数据、日志和**你自己的封面模板图**（`assets/templates/`），避免误提交个人素材。
- 除了你主动点「AI 润色」，插件**不会主动联网发请求**；抓取只访问你在设置里填的那些网站。

## 三、安装

### 前置条件

- 已经装好并能跑起来 **DSH**（`dsh web` 能打开界面）
- DSH 版本 **≥ 0.1.5-rc.1**（见 `package.json` 的 `dsh.engines`）
- Node.js 18 以上（构建脚本和测试要用；运行时用的是 DSH 自带的 Node）

### 安装步骤

```powershell
# 1) clone 到任意目录
git clone <本仓库地址> dsh-ai-news-workbench
cd dsh-ai-news-workbench

# 2) 用 link 方式装进 web 这个 profile（不复制文件，改代码就生效）
dsh plugin --profile web add link:<本插件的绝对路径>

# 3) 重启 DSH Web
```

> 第 2 步里的 `<本插件的绝对路径>` 换成你 clone 下来的目录，例如
> `D:\code\dsh-ai-news-workbench`。
> 如果你习惯用仓库里自带的挂载声明，也可以直接参考 `cordis.patch.yml`。

装完确认两件事（一般第 2 步已经自动做好）：

1. `~/.dsh/profiles/web/package.json` 的 `dependencies` 里有
   `"dsh-ai-news-workbench": "link:<你的路径>"`
2. 同一个文件的 `dsh.profile.bundles` 里有 `"dsh-ai-news-workbench"`
   （**只能出现一次**，重复会报重复注册）

### 卸载 / 回滚

1. 删掉 profile `package.json` 里 `dependencies` 的那一行和 `bundles` 里的那一项
2. 删掉 `~/.dsh/profiles/web/node_modules/dsh-ai-news-workbench`（是个 junction/软链）
3. 重启 DSH

数据都在 `~/.dsh/ai-news-workbench/`，卸载不会动它；想彻底清干净就手动删这个目录。

### 启用 / 禁用

插件市场里可以随时禁用（只写 `~/.dsh/profiles/web/.dsh-market/state.json` 的 `disabled` 列表）。
界面出问题时，最快的排查办法就是禁用 + 重启 —— 聊天功能完全不受影响。

## 四、配置（都在「⚙ 设置」里）

界面左上角的 **⚙ 设置** 进设置页，**保存按钮在页面顶部**，改完点一下即时生效（写在本机 JSON 里）。
设置分四块：

### 1) 模型（写文案 / AI 润色）—— 选填

见下一节。

### 2) 网站清单

每个网站四项：

| 字段 | 说明 |
|---|---|
| 名称 | 只是给你自己看的标签 |
| 网址 | **列表页**地址（不是文章页） |
| 抓取难度 | 普通 = 直接 HTTP 抓；困难（走浏览器）= 用 CDP 驱动本机 Chrome |
| 解析规则（折叠项） | 网站改版抓不到内容时再来调：`listSelector` / `titleSelector` / `linkSelector` / `dateSelector` |

右上角有「删除这个网站」；上面有「+ 加一个」。

### 3) 抓取参数

| 参数 | 默认 | 说明 |
|---|---|---|
| 超时（毫秒） | 10000 | 单个请求的超时 |
| 重试次数 | 3 | 失败退避重试 |
| 请求间隔下限 / 上限（毫秒） | 1500 / 3500 | 每个请求之间随机等待，别把人家网站打挂 |
| 每站最多抓几条 | 8 | 单站上限 |
| **抓取最近几天** | 1 | 1 / 3 / 5 / 7 天。判据是**详情页读到的真实发布日期**：读不到日期、或不在范围内的，一律丢掉 |
| Chrome 调试端口 | `http://127.0.0.1:9222` | 「困难」网站走浏览器抓时才用；需要在启动 Chrome 时加 `--remote-debugging-port=9222` |

### 4) 筛选规则关键词 + 可延展门槛

- 六项标准各自配一组关键词，命中所填的**任意一个**就算勾中这一项；勾中 1 项就进候选。
- 「可延展」不是关键词，而是两个门槛：原文里的**具体信息条数**和**正文字数**。

### ⑤ 封面标签的模板

「封面标签」模块顶部有「**打开模板文件夹**」：点一下会在资源管理器里打开模板目录，把你的模板图
（png / jpg / webp / gif，建议 3:4）丢进去，回来点「刷新」即可，文件夹里的图会列成缩略图，**点哪张用哪张**。

模板目录默认是插件自带的 `assets/templates/`（不存在会自动创建）。

## 五、模型配置（可选的「AI 润色」）

**不填也能用全部功能**，只是「④ 写文案」里的「AI 润色」按钮会禁用。

要启用就进 **⚙ 设置 → 1) 模型**，填三项：

| 字段 | 示例 |
|---|---|
| API 地址 | `https://api.deepseek.com/v1` |
| API Key | 你自己的 Key |
| 模型名 | `deepseek-flash` |

- 走的是 **OpenAI 兼容的 `/chat/completions`** 接口，所以其它兼容服务也能填（填到 `/v1` 为止，或直接填完整的 `.../chat/completions`）。
- **API Key 只存在本机** `~/.dsh/ai-news-workbench/settings.json`，不会提交到仓库，插件也不会把它发给除你填的那个地址以外的任何地方。
- DeepSeek 只出文字、**不能生图**；本插件也不做 AI 生图。

## 六、自己改代码

```bash
npm run build     # 改了 lib/client/ 下的文件后**必须跑**：把界面侧源码打成浏览器能吃的 bundle
npm test          # 一次跑全部测试
```

> ⚠ **客户端 bundle 是"注册工厂"格式**（`window.__ModuleLoader__.load({factory})`）。
> 千万别手改 `lib/client-dist/client.js`，也别在 `lib/client/` 里留下没被打包掉的 `import` / `export` ——
> 那会让排在这个插件后面的**所有**客户端插件一起挂掉，页面报 `Failed to load plugins`。
> 正确做法：改 `lib/client/` 下的源码 → `npm run build` → 重启 DSH + 浏览器 Ctrl+F5。

项目结构和实现细节见 [`索引.md`](./索引.md)（给 AI 助手/AI 编程工具看的导航图）和
[`docs/开发笔记.md`](./docs/开发笔记.md)（详细设计说明）。

## 七、测试

```bash
npm test
```

也可以用单独的入口：

| 命令 | 测什么 |
|---|---|
| `npm run test:host` | 主机侧冒烟（存储层、抓取解析、硬规则、本地生成） |
| `npm run test:api` | 接口端到端（假 ctx + 真 HTTP + 本地假新闻站） |
| `npm run test:ui` | 界面组件（用假 react 渲染后断言） |
| `npm run test:style` | 样式表注入 |
| `npm run test:bundle` | 打包格式（必须能被浏览器 `__ModuleLoader__` 注册） |
| `npm run test:combo` / `npm run test:e2e` | 按浏览器真实加载顺序整体跑一遍，抓 `Failed to load plugins` |

环境变量（都能不填）：

| 变量 | 用途 |
|---|---|
| `DSH_HOME` | DSH 数据目录（默认 `~/.dsh`） |
| `DSH_BIN` / `DSH_ENTRY` | 指定 dsh 可执行文件 / 入口，默认自动在 npx 缓存里找 |
| `XMT_NPX_NM` | 直接指定 npx 缓存的 `node_modules` 路径 |
| `XMT_TEST_PORT` | 端到端体检用的端口（默认 3099） |

**已知的长期红灯**：`ui.mjs` 约 10 项、`style.mjs` 约 4 项、`bundle-check.mjs` 1 项。
都是"弹窗几何用 `calc()` 量不到数值"那批断言，属于测试脚手架的限制，不影响实际功能。
